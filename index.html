tessera-specs · Tessera - Definition.md
整合式 HSM 代表產業在擴展硬體安全模組（HSM）與現代化金鑰管理方式上的一次演進。
原文Integrated HSM represents an evolution in how the industry can scale hardware security modules (HSMs) and modernize key management.
Tessera 是完全開源的軟體、韌體與晶片整合式 HSM 設計，提供透明度與一致性，並為各種 HSM 解決方案之間的互通建立共同基礎。和 Caliptra 一樣，Tessera 開放給整個產業協作。
原文Tessera is a fully open-source, software, firmware, and silicon integrated HSM design that provides transparency, consistency and establishes a common foundation for interoperability across HSM solutions. Like Caliptra, Tessera is available for industry-wide collaboration.

集中式 HSM 的挑戰

The challenges of Centralized HSMs
  • AI 與機密運算工作負載對密碼運算的需求成長速度，超過集中式 HSM 叢集能提供的服務量
    AI and confidential-compute workloads are scaling cryptographic demand faster than centralized HSM clusters can serve it
  • 每一次運算都是一趟到遠端 vault 的網路往返：延遲、擴展瓶頸，以及擴大的攻擊面
    Every operation is a network round trip to a remote vault
  • Latency, scaling bottlenecks, and an expanded attack surface
  • 在壓力下，團隊採用變通做法來達成效能目標
    Under pressure, teams adopt workarounds to hit performance targets
  • 信任悄悄流失的地方是這些變通做法，而不是 HSM 本身
    The workarounds — not the HSM itself — are where trust quietly erodes
  • CVM enclave 容易受到旁通道攻擊（SCA）與軟體錯誤影響
    CVM enclave susceptible to SCA and SW bug
  • 憑證與金鑰仍以明文存在 enclave 中，而不是在專用的 HSM 邊界內
    Certs and Keys still live in plaintext in enclave instead of dedicate HSM boundary

業界常見的金鑰管理反模式

Key Management Antipatterns
  • 關鍵金鑰在 HSM 邊界之外產生
    Critical keys generated outside the HSM boundary
  • 金鑰匯出到保證等級較弱的工作負載環境
    Key export into workload environments with weaker assurance
  • 為了韌性在本地快取金鑰，繞過 HSM
    Local key caching for resilience, bypassing the HSM
  • 為了延遲而採用、削弱隔離的變通做法
    Latency-driven workarounds that weaken isolation
  • 過度共用的安全網域造成治理擴散
    Governance sprawl across over-shared security domains
  • 金鑰無法在不同廠商或雲端之間移動，除非重新產生、使用專有傳輸，或冒明文暴露的風險
    Keys can't move across vendors or clouds without re-generation, proprietary transport, or plaintext exposure risk

TESSARA：開放的 iHSM 標準

TESSARA: An Open iHSM Standard
  • 定義 iHSM 的開放 OCP 標準
    An open OCP standard that defines the iHSM
  • 今天在 OCP Global Summit 2026 發表，由 Marvell、Microsoft 與 Oracle 共同開發
    Unveiled today at OCP Global Summit 2026 — jointly developed by Marvell, Microsoft, and Oracle
  • FIPS 140-3 Level 3：與工作負載一起放在伺服器托盤中的專用安全模組
    A dedicated security module co-located with the workload in the server tray
  • 開放晶片模式：Caliptra 為硬體信任根帶來的同一套開放模式，現在用在金鑰上
    The same open model Caliptra brought to hardware root of trust, now for keys
  • 延伸集中式 HSM：延伸集中式 HSM 的信任邊界，讓金鑰在托盤本地、緊鄰工作負載的地方保存與使用
    Extends the centralized HSM trust boundary so keys are maintained and used locally on the tray, next to the workload

Slide 9

DARC

DARC
  • 在 HSM 之間移動金鑰的標準後量子安全協定
    Standard PQ Safe Protocol to move keys between HSMs.
  • 來源（Central HSM）：擁有金鑰；產生一次性的傳輸金鑰，並用它包裝金鑰
    Owns the key. Mints a single-use transfer key and wraps under it.
  • 傳輸：經過證明（attested）的 HPKE 密封金鑰
    ATTESTED HPKE SEALED Key
  • 目標（Integrated HSM）：解包到自己的 masked-key 網域，保留金鑰屬性
    Unwraps into its own masked-key domain, attributes preserved.
  • 不同製造商、不同型號、沒有共同的製造商信任鏈，而且金鑰從未被標記為可匯出
    Different make, different model, no shared manufacturer chain — and the key is never marked extractable.
