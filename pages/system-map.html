系統地圖：雲端、伺服器、PCIe 卡、晶片之間的關係

四層之間的關係，一次看懂

雲端 ↔ 晶片：靠憑證，不靠網路

晶片不直接連雲端。所有雲端互動（金鑰傳輸、證明、備份）都經過 VM 裡的 SDK 轉送，晶片只負責驗證憑證鏈：製造商 → IDevID，Owner → AOAC，分區 Owner → POAC。所以就算網路斷了，HSM cache 模式還是能繼續運作。

VM ↔ 晶片：VF 直通，繞過 hypervisor

每個租戶的 VM 透過 SR-IOV 拿到一個 VF，經過 IOMMU 直接 DMA 到晶片。TDISP 會把 VF 鎖成 TEE 的 TDI，IDE 則加密 PCIe 連線。營運者（hypervisor）只能透過 PF 建立或刪除分區，看不到任何分區裡的金鑰。

韌體 ↔ 晶片：Caliptra 管開機，M7 跑 HSM

Caliptra 2.2 從 QSPI flash 驗證並載入韌體，推導 DICE 身分，處理 SPDM 證明。HSM 邏輯（tessera-sw 的 fw/core）跑在控制核心上，透過 key mover 和 pool manager 使用加速器（tessera-rtl）。

金鑰平常放在哪裡？

主機記憶體和雲端儲存。Offloaded 模式下，金鑰都是 AES-GCM 遮罩過的 blob，由 VM 保管，每次使用時才由 key mover 在晶片裡解開。晶片內只長期保存種子（OTP）和少量的 pinned key（GSRAM Key Vault）。

Sidecar 是什麼角色？

還沒有實體晶片之前，把同一套 HSM 韌體編成軟體，跑在 SEV-SNP 機密 VM 裡，再透過 vsock 提供服務。API 和實機相容，但沒有硬體邊界；而且目前的裝置秘密寫死在程式碼裡（資安審查 H-1）。

商業上的控制點

誰掌握 Owner CA（AOTA/POTA/DATA），誰就掌握這顆 HSM 能接收誰的金鑰。這是雲端業者和企業之間真正的權力分配點；晶片廠和 IP 廠的價值則集中在 L3 邊界內那些還沒公開的方塊。

依據 tessera-specs v0.5.0（CRD、Deployment Models、DARC、Sealing）與 tessera-sw 3281212、tessera-rtl fc5e739 的程式碼繪製。晶片內部方塊依 CRD 的需求章節排列，不是實際的 floorplan。
