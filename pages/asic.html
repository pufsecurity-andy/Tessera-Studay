03效能目標

CRD 的 PERF 表，加上 key mover 與 host memory hasher 的速率需求。

CRD「Performance Requirements」開頭兩段

Tessera 的效能需求主要由密碼服務工作負載驅動，包括安全金鑰釋放、簽章、驗章、證明、金鑰交換與後量子密碼。PQ 運算必須達到與 ECC 簽章相同的吞吐量，以支援 hybrid 簽章服務。所有 RSA 與 ECC 運算假設在同一個加速器 pool 上執行，因此 RSA 與 ECC 運算所列的效能需求是各自單獨達成，而不是同時達成。PQC 加速器上的 ML-KEM 與 ML-DSA 運算也是如此。

原文Tessera performance requirements are driven primarily by cryptographic service workloads including secure key release, signing, verification, attestation, key exchange, and post-quantum cryptography. The PQ operations must match the ECC signing throughput numbers to allow for hybrid signing services. All RSA and ECC ops are assumed to be performed on the same pool of accelerators, so the performance requirements listed for RSA and ECC operations are expected to be attained individually, not concurrently. The same holds true of ML-KEM and ML-DSA operations on the PQC accelerators.

Hybrid 公鑰運算代表 PQC 與傳統（RSA/ECC）加速器必須同時以各自規定的全速運作。此外，多數公鑰運算都需要用到 AES 與雜湊引擎。同一個 pool 中的混合負載，所佔容量與規定的 ops 速率成反比。例如，每秒 2000 次 RSA 4K 簽章的工作負載約佔 RSA/ECC pool 容量的 10%，應該能與每秒 180,000 次 ECC Sign p-256 的工作負載並存。

原文Hybrid public key operation means that the PQC and traditional (RSA/ECC) accelerators must operate at their full specified rate concurrently. Furthermore, the AES and hashing engines are needed in most public key operations. For mixed loads in one pool, the capacity taken is inversely proportional to the specified ops rate. For example, a workload of 2000 RSA 4K signs per second takes about 10% of the RSA/ECC pool capacity and should be able to coexist with a workload of 180,000 ECC Sign p-256 operations per second.

04實作現況：規格 vs 開源程式碼
